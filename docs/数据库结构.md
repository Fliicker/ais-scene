# AIS 数据库结构说明

## 1. 数据库概览

数据库文件：`D:\Projects\ais\data\ais0416.db`

该文件是一个 SQLite 数据库，存储 AIS 船舶数据。整体结构由 1 张船舶信息表和 4 张按日期拆分的轨迹表组成：

| 类型 | 表名 | 说明 |
| --- | --- | --- |
| 船舶信息表 | `ship` | 以 `mmsi` 为主键，记录船舶静态信息、当前状态和分类信息 |
| 轨迹表 | `locus20260413` | 2026-04-13 相关 AIS 轨迹点 |
| 轨迹表 | `locus20260414` | 2026-04-14 相关 AIS 轨迹点 |
| 轨迹表 | `locus20260415` | 2026-04-15 相关 AIS 轨迹点 |
| 轨迹表 | `locus20260416` | 2026-04-16 相关 AIS 轨迹点 |

数据库中没有显式外键约束。轨迹表和 `ship` 表通过 `mmsi` 字段形成逻辑关联。

## 3. 表结构

### 3.1 `ship` 船舶信息表

`ship` 表以 `mmsi` 为主键，记录船舶识别信息、尺寸、航向、航速、目的地、AIS 类型和分类等信息。

建表结构：

```sql
CREATE TABLE ship (
    mmsi text PRIMARY KEY,
    cjsj text,
    sjly text,
    imo text,
    cbmc text,
    zwmc text,
    cbhh text,
    acblx text,
    cd text,
    kd text,
    cb_aisdwlx text,
    cbcs text,
    mdg text,
    cb_aislx text,
    cbhx double,
    dqhs double,
    cb_aisdwlx_name text,
    class_type text
)
```

字段说明：

| 字段 | 类型 | 约束 | 含义 |
| --- | --- | --- | --- |
| `mmsi` | `TEXT` | 主键 | 船舶 MMSI 编号，船舶唯一标识 |
| `cjsj` | `TEXT` |  | 采集时间 |
| `sjly` | `TEXT` |  | 数据来源 |
| `imo` | `TEXT` |  | IMO 编号 |
| `cbmc` | `TEXT` |  | 船舶名称 |
| `zwmc` | `TEXT` |  | 中文名称 |
| `cbhh` | `TEXT` |  | 船舶呼号 |
| `acblx` | `TEXT` |  | 船舶类型编码 |
| `cd` | `TEXT` |  | 船长 |
| `kd` | `TEXT` |  | 船宽 |
| `cb_aisdwlx` | `TEXT` |  | AIS 定位类型编码 |
| `cbcs` | `TEXT` |  | 船舶吃水或相关状态字段，库中以文本存储 |
| `mdg` | `TEXT` |  | 目的港或目的地信息 |

### 3.2 轨迹表

4 张轨迹表结构完全一致，均以 `(mmsi, jssj)` 作为联合主键，表示同一船舶在同一接收时间只有一条轨迹记录。

适用表：

```text
locus20260413
locus20260414
locus20260415
locus20260416
```

建表结构：

```sql
CREATE TABLE locusYYYYMMDD (
    mmsi text,
    jssj text,
    zbjd double,
    zbwd double,
    dqhs double,
    cbhx double,
    cbcs text,
    class_type text,
    PRIMARY KEY(mmsi, jssj)
)
```

字段说明：

| 字段 | 类型 | 约束 | 含义 |
| --- | --- | --- | --- |
| `mmsi` | `TEXT` | 联合主键第 1 列 | 船舶 MMSI 编号 |
| `jssj` | `TEXT` | 联合主键第 2 列 | 接收时间或轨迹点时间，格式为 `YYYY-MM-DD HH:MM:SS` |
| `zbjd` | `double` |  | 坐标经度 |
| `zbwd` | `double` |  | 坐标纬度 |
| `dqhs` | `double` |  | 当前航速 |
| `cbhx` | `double` |  | 船舶航向 |
| `cbcs` | `TEXT` |  | 船舶吃水或相关状态字段，库中以文本存储 |
| `class_type` | `TEXT` |  | 数据分类或船舶分类编码 |

每张轨迹表都有一个由主键自动生成的唯一索引：

| 表名 | 索引名 | 唯一 | 字段 |

## 4. 逻辑关系

数据库没有声明外键，但业务上存在如下关系：

```text
ship.mmsi = locusYYYYMMDD.mmsi
```

关系含义：

| 关系 | 说明 |
| --- | --- |
| `ship` 到轨迹表 | 一艘船可以对应多条轨迹点 |
| 轨迹表到 `ship` | 每条轨迹点通过 `mmsi` 关联一条船舶信息 |
| 轨迹表之间 | 按日期分片保存，表结构一致，可通过 `UNION ALL` 合并查询 |

当前数据中，轨迹表出现的 MMSI 均存在于 `ship` 表，说明轨迹数据和船舶信息表在 MMSI 维度上是完整可关联的。

## 6. 查询建议

### 6.1 查询某艘船的轨迹

由于轨迹表按日期拆分，查询单日轨迹时可直接命中对应日期表：

```sql
SELECT *
FROM locus20260416
WHERE mmsi = '413962853'
ORDER BY jssj;
```

查询跨日轨迹时，可使用 `UNION ALL`：

```sql
SELECT * FROM locus20260413 WHERE mmsi = '413962853'
UNION ALL
SELECT * FROM locus20260414 WHERE mmsi = '413962853'
UNION ALL
SELECT * FROM locus20260415 WHERE mmsi = '413962853'
UNION ALL
SELECT * FROM locus20260416 WHERE mmsi = '413962853'
ORDER BY jssj;
```

### 6.2 关联船舶信息和轨迹

```sql
SELECT
    l.mmsi,
    s.cbmc,
    s.zwmc,
    l.jssj,
    l.zbjd,
    l.zbwd,
    l.dqhs,
    l.cbhx,
    l.class_type
FROM locus20260416 l
JOIN ship s ON s.mmsi = l.mmsi
WHERE l.mmsi = '413962853'
ORDER BY l.jssj;
```

### 6.3 按空间范围查询轨迹点

```sql
SELECT *
FROM locus20260416
WHERE zbjd BETWEEN 118.5 AND 119.0
  AND zbwd BETWEEN 31.8 AND 32.2
ORDER BY jssj;
```

当前库只存在 `(mmsi, jssj)` 主键索引，没有经纬度索引。如果空间范围查询频繁，建议后续增加针对 `zbjd`、`zbwd` 的索引，或引入 SQLite R-Tree 虚拟表维护空间索引。

## 7. 建模与使用注意事项

1. 轨迹表以日期命名，但部分表包含前一日较晚时间的数据。例如 `locus20260416` 的最早时间为 `2026-04-15 21:06:08`。业务查询时应以 `jssj` 字段作为最终时间条件，而不是只依赖表名日期。
2. `jssj`、`cjsj` 使用 `TEXT` 存储时间，当前格式可按字符串排序得到正确时间顺序，但需要保持 `YYYY-MM-DD HH:MM:SS` 格式一致。
3. `cbcs`、`cd`、`kd` 等看起来像数值的字段在库中以 `TEXT` 存储，进行数值计算前需要显式转换并处理空字符串。
4. 数据库未声明外键，应用层需要自行保证 `mmsi` 关联一致性。
5. 轨迹表只有联合主键索引，适合按 `mmsi` 查询某船时间序列；如果需要按时间范围扫描全量船舶，建议增加单独的 `jssj` 索引。
